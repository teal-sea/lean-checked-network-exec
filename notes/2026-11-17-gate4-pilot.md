## Semantics chosen (checked 18:44Z with #eval in probe/Probe.lean)
- `>>` on i64: `Int.shiftRight`. `Int.shiftRight (-257) 8 = -2`, `Int.shiftRight (-1) 8 = -1` (floor).
- `/` on i64: `Int.tdiv` (toward zero, Rust's rule). `Int.tdiv (-7) 2 = -3`. `Int.ediv`, `Int.fdiv` and
  `/` on Int give -4. Numerator >= 0 and denominator > 0 here, so all agree on the values that occur.
- `& 255`: `Int.emod x 256` (`Int.emod (-1) 256 = 255`; `Int.tmod (-1) 256 = -1`).
- Aeneas (toolchain/aeneas/backends/lean, read only): `IScalar.ShiftRight_spec` gives
  `z.val = x.val >>> y.val`; the division spec gives `Int.tdiv`. Same operations as chosen here.

## Why base 2^64 was slow (sources read 19:41Z)
- Installed toolchain, src/lean/Init/Data/Hashable.lean line 15: `instance : Hashable Nat where hash n := UInt64.ofNat n`.
- leanprover/lean4 tag v4.35.0 (raw.githubusercontent.com, copies in logs/lean_*): src/Lean/Expr.lean line 25-27
  `Literal.hash | .natVal v => hash v`, line 513 `| .lit l => mkData (mixHash 3 (hash l))`;
  src/runtime/object.cpp line 1879 `lean_uint64_of_big_nat` returns `mpz_value(a).mod64()`;
  src/kernel/expr.cpp line 81-84 `hash_core` calls `lean_expr_hash`.
  So the hash of a Nat literal term depends only on the literal mod 2^64. Every multiple of 2^64 hashes alike.
  (src/runtime/mpz.h line 74 `mpz::hash` returns the low 32 bits; that one is not the term hash.)
- Not checked: whether lean-checked-network's own slow runs (B = 2^208 in transformer/lean) had this cause.
